# Школы по источникам (демо)

Раздел показывает, как состав и структура научной школы могут описываться по опубликованным источникам. Он не вычисляет принадлежность к школе из научного руководства и не изменяет базу данных. Общий контекст приложения используется для проверки доступности генеалогического дерева каждой персоны.

## Переход к деревьям научного руководства

Персоналии, для которых в базе найдены записи научного руководства, показаны в Markmap подчёркнутыми ссылками. Клик по имени открывает вкладку «Построение деревьев» в новой вкладке браузера и автоматически строит общее дерево. Кружок узла сохраняет сворачивание и разворачивание ветвей. Ссылка поддерживается также для центрального узла основателя и в экспортируемом HTML.

В двустороннем Markmap целые группы распределяются влево и вправо с минимальной разницей по числу конечных листьев. После источниковой сверки 13.10.2026 четыре основные ветви содержат 28, 13, 4 и 5 персон; минимальное распределение целых ветвей даёт 28 и 22 листа. Цвета групп и порядок внутри каждой стороны сохраняются. Распределение учитывает полную структуру дерева, поэтому сворачивание и скрытие узлов не переносят группы на другую сторону. Этот же алгоритм используется во вкладке построения деревьев и в экспортируемом HTML.

Сопоставление учитывает порядок ФИО, «ё/е» и явно указанную другую фамилию. Разные полные имена с одинаковыми инициалами не объединяются. Неоднозначные и сокращённые имена не получают ссылку автоматически. Источниковые роли и структура школы при этом остаются неизменными.

## Чем отличается от генеалогических школ

Генеалогические разделы строятся вокруг связей научного руководства. Этот демо-раздел хранит источниковые атрибуции: один источник может назвать участника учеником, другой — сотрудником или представителем круга. Интерфейс показывает эти формулировки отдельно и помечает нормализованные роли как систематизацию.

## Каталог данных

Файлы располагаются в каталоге `data/source_schools/`. Runtime-чтение этих статических справочных файлов вынесено в общий слой `core/source_schools/`, поэтому вкладка Streamlit не открывает JSON напрямую. Каждый файл должен быть UTF-8 JSON и иметь верхние блоки:

- `школа`;
- `демо_представление`;
- `контроль_качества`;
- необязательный служебный блок `_processing_metadata`, который интерфейс не показывает.

Идентификатор школы берётся из `школа.идентификатор_школы`, а подпись в выпадающем списке — из `демо_представление.название_в_выпадающем_списке`. Значения должны быть непустыми и уникальными в каталоге.

## Проверка связности

Загрузчик проверяет уникальность идентификаторов персон, источников, подтверждений и исследовательских групп. Также проверяются ссылки из персон, источниковых атрибуций, подтверждений, групп, направлений, поколений, хронологии и историографических позиций. Значения уверенности должны быть числами от `0` до `1`. Сводные показатели пересчитываются по данным и сравниваются с блоками `демо_представление.сводные_показатели` и `контроль_качества`.

## Как добавить школу

1. Подготовьте новый JSON-файл с той же общей структурой.
2. Поместите файл в `data/source_schools/`.
3. Убедитесь, что идентификатор школы и название для выпадающего списка не повторяются.
4. Запустите проверку:

```bash
pytest -q tests/test_source_schools_data.py tests/test_source_schools_tables.py tests/test_source_schools_tab.py
```

После успешной проверки новая школа появится в выпадающем списке без изменения кода интерфейса.

## Ограничения MVP

Раздел не поддерживает редактирование JSON через интерфейс, загрузку файлов пользователем и автоматическое извлечение фактов из публикаций.

## Обновление требований к демонстрации школ по источникам

Раздел использует подготовленный JSON `data/source_schools/vygotsky_school_sources_demo.v1.json`. Для каждой персоны обязательно реальное имя в поле `имя` или `полное_имя`; placeholder-записи вида `Представитель N`, `Участник N`, `Person N` и демонстрационные описания вклада запрещены валидатором. Источники должны содержать поле `библиографическое_описание`; краткие технические идентификаторы источников не выводятся пользователю.

В режиме «Источники и подтверждения» первым показывается нумерованный список использованных источников. Нумерация следует порядку JSON или полю `порядок`, если оно задано для всех источников. Описание берётся из `библиографическое_описание`; DOI, URL и дата обращения добавляются только при отсутствии дубля в исходном описании. Формат описывается как близкий к ГОСТ, без заявления о сертифицированной автоматической проверке.

В режиме «Обзор» основное положение узлов задают четыре взаимоисключающих типа связи с основателем: прямое руководство или обучение, прямое сотрудничество, внешнее прямое взаимодействие и косвенная преемственность. Основатель служит корнем и не дублируется в категориях. Загрузчик проверяет, что каждая прочая персона входит ровно в одну категорию.

Историческая группа, период и научное направление доступны как три одновременных многозначных измерения. Внутри каждого измерения можно выбрать несколько значений; они объединяются по правилу «ИЛИ». Активные измерения пользователь компонует по правилу «И» (пересечение) или «ИЛИ» (объединение). Режим отображения либо подсвечивает соответствующих персон оранжевым и затеняет остальных, либо скрывает остальных визуально. В обоих режимах полный граф, порядок узлов и структура четырёх типов связи сохраняются, поэтому переключение не меняет расположение персон и позволяет сравнивать срезы.

### Канонические назначения и полнота фильтров

Для документов с полем `школа.классификационные_назначения` все три измерения используют именно этот реестр. Принадлежность не извлекается из свободного текста или сокращённого списка `основные_представители`. Описательные каталоги содержат стабильные идентификаторы; списки их участников являются совместимой проекцией реестра. Один и тот же источник членства применяется к дереву, карточкам, таблицам, счётчикам и выгрузкам. Старые документы без реестра сохраняют поддержку явных каталожных списков.

Рабочие выборки принимают статусы `подтверждено` и `интерпретация`. Последний обозначает редакторское тематическое или временное отнесение с адресным источниковым основанием, а не неподтверждённую гипотезу. В интерфейсе нет переключателя включения непроверенных назначений. Служебное значение «Не размечено / недостаточно источниковых данных» сохраняет видимость персон без классификации и не создаёт им принадлежность ради полного охвата.

В данных Выготского четыре прежние непроверенные принадлежности вынесены в `журнал_классификационных_гипотез`: Лебединский и Каулина в московской клинической группе, клинический исследовательский контекст Каулиной и клинический период Морозовой 1934–1936. Они не участвуют в фильтрах. Основания их обсуждения доступны в режиме «Расхождения и качество данных».

### Источниковое дополнение 13.10.2026

В основном составе остаются 51 персона. Библиография расширена до 35 источников: добавлены русская автобиография Лурии (1982), биография Выготского Выгодской и Лифановой (1996), книга А. А. Леонтьева (1990) и издание записных книжек Выготского (2017). Проверенные локальные экземпляры отмечены контрольными суммами; непроверенные URL не создаются. Всего 99 подтверждений и 375 активных классификационных назначений. Журнал содержит все 28 результатов проверки с печатными страницами, видами свидетельств, решениями и ограничениями.

Добавлены контексты клинических конференций ЭДИ 1931 года и конференции 27–29 октября 1933 года. Участие в конференции отделяется от штатной работы. Проект сотрудников ВИЭМ 1934 хранится как план и не создаёт назначений фактического трудоустройства. Новые консультанты Озерецкий, Аккерман и Аркин, а также уточнённая Т. А. Власова сохранены в кандидатах: установленный контакт не превращается автоматически в утверждение об устойчивом членстве или ученичестве.

Вересотская и Лебединский отнесены к A1 по адресным свидетельствам непосредственного научного руководства; Мира Левина — по индивидуальной атрибуции «ученица» в биографии 1996. Формальная аспирантура и диссертационное руководство из этих формулировок не выводятся. Шемякин перенесён из A4 в A3 как участник прямого критического обсуждения; он не обозначается сторонником теории.

В карточках и выгрузках сохраняются разночтения аспирантуры Шиф, начала руководства Элькониным, рождения Конниковой, отчества Аснина, трактовки ученичества Менчинской и проблемной даты возвращения Зейгарник у Лурии. Рождение Конниковой оставлено неизвестным при вариантах 1907/1909; смерть Гешелиной 1972? не превращена в установленный год. Письмо, воспоминание, запись Выготского, редакторский комментарий и редакторская реконструкция различаются. Русская и английская редакции автобиографии Лурии не считаются независимыми свидетельствами.

Классификация по типу связи является аналитической систематизацией, а не новым источниковым фактом. Исходные формулировки ролей и историографические расхождения сохраняются в карточках персон. Дерево не создаёт неподтверждённые отношения «учитель — ученик» между персонами.

Поддерживаются выгрузки JSON, CSV, XLSX, TXT, HTML, PNG и ZIP. Полный ZIP содержит исходный JSON, книгу Excel, CSV по представителям, источникам, подтверждениям и рёбрам дерева, классификационные назначения и их основания, текстовый список источников, PNG дерева и интерактивное HTML-дерево. Разночтения и ограничения включены в таблицу представителей; полный журнал сохраняется в исходном JSON.

При добавлении новой школы нужно подготовить JSON без placeholder-данных, указать реальные библиографические описания, проверить ссылки персон, источников, подтверждений, групп, направлений и поколений, а затем выполнить:

```bash
pytest -q tests/test_source_schools_data.py tests/test_source_schools_tables.py tests/test_source_schools_bibliography.py tests/test_source_schools_tree.py tests/test_source_schools_export.py tests/test_source_schools_tab.py tests/test_streamlit_app_smoke.py
pytest -q
```
